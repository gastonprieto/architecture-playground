# Sessions & Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Model where user sessions live (service memory, a database, JWT) and who authenticates (services, or the API gateway), per `docs/sessions-spec.md`.

**Architecture:**
- **Cliente:** gets users, per-user cookies and an auth mode.
- **Responses** carry a meta patch: `setSession` / `authError`.
- **DSL:** gains a `session` step.
- **Database:** gets a type (icon, latency, volatility) and stores sessions.
- **LB:** gains sticky sessions by cookie.
- **Reverse Proxy:** gains a real auth mode in place of the random rejection.

**Tech Stack:** existing.

**Spec:** `docs/sessions-spec.md` (binding). Also `docs/dsl-spec.md` and `docs/spec.md`.

## Review Focus

1. **Every 401 path reaches the right user.** A per-user cookie is set and cleared on the user who made the request (`meta.userIndex`), even with N users interleaved and responses arriving out of order.
2. **`session` against a database that goes down mid-check.** The step fails (503 or the modifier) and the occupy slot is released.
3. **Sticky map entries for removed or down servers** fall back to the algorithm without crashing.
4. **A key-value database toggled off/on with the sim paused, or within one tick,** still loses its sessions.
5. **`authFailRate` migration** works for every entry path (boot, link, import, preset).

### Task 1: Engine reply meta + Cliente users, auth and cookies

**Files:**
- `src/engine/registry.ts` (`reply` signature), `src/engine/simulation.ts`
- `src/components/client.ts`
- Tests: `tests/engine/*`, `tests/components/client-service.test.ts` (or a new `tests/components/client-sessions.test.ts`)

**Interfaces:**
- `ctx.reply(msg, { status, code, meta?: Partial<Message['meta']> })`. The patch is merged into the response's `meta`.
- `Message['meta']` gains:
  - `credentials?: boolean`
  - `sessionId?: string`
  - `setSession?: string`
  - `authError?: 'session-lost' | 'unauthenticated'`
  - `userIndex?: number`
  - `sessionOp?: 'check' | 'create'`
- **Cliente config:**
  - `users`: number 1..50, default 1.
  - `auth`: select `'login' | 'none'`, default `'login'`.
- **Cliente state:** `next` (round-robin cursor) and `cookies: (string | null)[]` of length `users`. It adapts when `users` changes: new users have no cookie, removed users are dropped.
- **Cliente per message:**
  - Picks user k (round robin) and sets `meta.userIndex = k`.
  - `clientIp` is `"<ip>#<k+1>"` when users > 1.
  - With login: `credentials = true`, plus `sessionId` when the user has a cookie.
- **Cliente `onResponse`** (where `recordsMetrics` happens):
  - `setSession` → store the cookie for that `userIndex`.
  - 401 with `session-lost` → clear it.
- **Stats/state** exposes the number of logged-in users for the UI: `state.cookies`.

  - Round-robin users carry `userIndex` and `clientIp#k`.
  - Cookie set and cleared per user, with out-of-order responses.
  - `auth none` sends no credentials.
  - Changing `users` resizes the cookies.

### Task 3: DSL `session` step

**Files:**
- `src/components/behavior/{ast,parse,validate,run}.ts`
- Tests: `tests/components/behavior/*`

**Interfaces:**
- AST step: `{ kind: 'session'; line; store: { kind: 'memory' } | { kind: 'jwt' } | { kind: 'database'; target: string }; mod?: Mod }`.
  - `nowait` is not allowed: it gives a `nowait-with-or`-style error (choose an apt code, `session-nowait`, and add it).
  - `memory` and `jwt` are keywords. A database literally named "memory" must be quoted.
- **Validation:** the target must be a connected `database`. Otherwise `not-connected`, or `wrong-verb` with a suggestion (`query`/`call`). Add the code `session-target` if `wrong-verb` doesn't fit.
- **Run semantics** follow spec §4 exactly:
  - Login sets a pending `setSession` that the final reply of the handler carries (`ctx.reply` meta).
  - A 401 ends the handler with `authError` in the meta.
  - In event/message handlers the step is a no-op.
- **Memory sessions:**
  - Live in component state `sessions`.
  - Cleared on the component's up=false transition, detected like Task 2.
- **Database:**
  - A child request with `sessionOp` and `sessionId` (`create` uses a new id `sid:<msg.id>`).
  - Response 200 → continue, 404 → `session-lost`, error → step failure with modifiers.
- **JWT:** `jwt:<msg.id>` on login; any `jwt:` prefix is valid; a `sid:` cookie gives `session-lost`.

- [ ] Write failing engine-level tests for every row of the spec §4 table × {memory, database, jwt}, plus:
  - The database goes down mid-check (Review Focus 2).
  - `or continue` on a down store.
  - The memory store cleared on down.
  - A 6-user client against 3 memory services behind a round-robin LB without sticky shows 401 session-lost churn.
- [ ] Run RED, implement, run GREEN.
- [ ] Commit `feat(dsl): session step (memory, database, jwt)`.

### Task 4: LB sticky sessions + Reverse Proxy auth

**Files:**
- `src/components/load-balancer.ts`, `src/components/reverse-proxy.ts`
- `src/persistence/serialize.ts` or the UI graph-entry backfill (where `backfillClients` lives) for the `authFailRate` migration
- Tests: `tests/components/load-balancer.test.ts`, `tests/components/reverse-proxy.test.ts`, migration test

**LB:**
- `sticky` boolean, default false.
- `state.sticky: Record<sessionId, NodeId>`, learned in `onResponse` from `setSession` (the target that answered).
- **Routing:** if the cookie is known and its target is available, use it; otherwise use the algorithm and update the map. Health checks apply first.
- **Tests:**
  - With sticky, 6 users stick to their server and have 0 session-lost.
  - Taking that server down moves its users, who get one 401 and then re-login.
  - Without sticky, there is churn.

**Proxy:**
- Remove `authFailRate`. Add `auth`: `'none' | 'credentials' | 'jwt'`, default `'none'`, behaving per spec §8.
- JWT issuance appends `setSession` to the response in the proxy's `onResponse`. The proxy must track which forwarded requests need a token, keyed by request id.
- **Migration:** at every graph entry, a reverse-proxy with `authFailRate > 0` gets `auth: 'credentials'` and `authFailRate` is removed. Use a pure helper `migrateGraph(graph)` next to `backfillClients`, and compose them. Covered with a test per entry path (Review Focus 5).

- [ ] Write failing tests, run RED, implement, run GREEN.
- [ ] Commit `feat(lb,proxy): sticky sessions and gateway authentication`.
