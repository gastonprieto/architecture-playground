# Graph DSL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PlantUML-like text format for whole graphs that is easy to write by hand. Exportar writes it, Importar accepts it (or the old JSON), and a "Texto" popup edits the current graph as text.

**Architecture:** Pure modules in `src/persistence/dsl/`:
- `values.ts`: field values ↔ text.
- `parse.ts`: text → graph + errors.
- `layout.ts`: positions for nodes without `at`.
- `print.ts`: graph → canonical text.

The JSON format stays the internal one (`localStorage`, `#g=` link). The UI wires the DSL into Toolbar export/import and a new `GraphTextDialog`, modeled on `BehaviorEditor`.

**Tech Stack:** TypeScript, React 19, zustand, vitest + @testing-library/react.

**Spec:** `docs/graph-dsl-spec.md` (binding). Also `docs/dsl-spec.md` (the behavior DSL embedded in `behavior:` blocks).

### Task 2: Parser (text → graph)

**Files:**
- Create: `src/persistence/dsl/parse.ts`
- Test: `tests/persistence/dsl-parse.test.ts`

**Interfaces:**
- Consumes: Task 1 (`parseFieldValue`, `unquote`, `suggest`, `GraphDslError`, `COL`, `ROW`), `defaultRegistry`, `defaultConfig` (`src/engine/registry.ts`).
- Produces:
  - `export type GraphDslResult = { ok: true; graph: Graph } | { ok: false; errors: GraphDslError[] }`
  - `export function parseGraphDsl(text: string): GraphDslResult`. In this task, nodes without `at` get `{ x: 0, y: 0 }`. Task 3 replaces that with the layout.
  - `export function parseDocument(text: string): { graph: Graph; placed: Set<NodeId>; errors: GraphDslError[] }`: the internal entry Task 3 uses.
  - `export const TYPE_KEYWORDS: Record<string, string>`: keyword → registry type, including the aliases `db`, `lb`, `proxy` (spec §4).
  - `export function slugify(name: string): string`: lowercase, diacritics removed (NFD), runs of non-`[a-z0-9]` → `-`, trimmed of `-`. Empty → `'node'`.

**Algorithm notes** (the parts tests don't fully determine):
1. **Scan.**
   - Strip a leading BOM and split on `/\r?\n/`; line numbers are 1-based.
   - `behavior:` blocks are collected **before** comment stripping. A block runs while lines are blank or have more leading spaces than the `behavior:` key. Its lines are dedented by `keyIndent + 2`, trailing blank lines are dropped, and the text is joined with `\n` plus a final `\n` (empty block → `''`).
2. **Comments**, outside blocks and outside quotes: `#` at the first non-space position, or `#` followed by space/end of line. Then trim the end of the line.
3. **Tabs.** A tab in the indentation outside a block → `tab`.
   - Indented lines (2 spaces) belong to the last declaration.
   - Any other indent, or an indented line with no declaration above it → `bad-indent`.
4. **Header.** `@architecture vN` is optional and allowed only as the first statement; `v1` is the only valid version (otherwise `unknown-version`).
5. **Edges.**
   - A line containing `-->` outside quotes/brackets is an edge line. Split it on `-->`, then each group on `,` outside quotes/brackets, then each target into `ref` + optional `[attrs]`.
   - **Attrs:** tokens split on whitespace/commas outside quotes:
     - `path X` / `/…` → `pathPrefix`
     - `weight N` / `xN` → weight
     - `event X` / anything else → `eventType`
     - Two rules → `duplicate-rule`. A bad weight or a lone `path`/`event` → `bad-attribute`.
6. **Declarations.**
   - The first word must be in `TYPE_KEYWORDS` (else `unknown-type` with a suggestion).
   - Parse the rest from the end with ``/^(.*?)(?:\s+as\s+([\p{L}\p{N}_-]+))?(?:\s+at\s+(-?\d+(?:\.\d+)?)\s*,\s*(-?\d+(?:\.\d+)?))?$/u``, so `Data at rest` stays a name.
   - Names are split on commas outside quotes. An empty name → `missing-name`. `as`/`at` with more than one name → `multi-alias`.
7. **Config lines.**
   - Each is `key: value` (no `:` → `missing-colon`). The key must be a field of the type, excluding `name` (else `unknown-key` with a suggestion).
   - A repeated key → `duplicate-key`.
   - A `behavior` field must use the block form (an inline value → `bad-value`). A non-behavior key with a block → `bad-value`.
   - The config applies to every name of the declaration.
8. **Ids.**
   - Aliases first (a duplicate → `duplicate-alias`). Then `slugify(name)` for the rest, suffixed `-2`, `-3`… past taken ids.
   - Config = `{ ...defaultConfig(def), name, ...parsed }`; position = `{ x: col * COL, y: row * ROW }`.
9. **Refs** are resolved after all declarations, so order does not matter.
   - Alias first, then exact name.
   - A name with several nodes → `ambiguous-ref` (`params.name`).
   - No match → `unknown-ref` with a suggestion over names + aliases.
   - Edge id `${source}-${target}`; a repeated pair → `duplicate-edge`.
10. **Errors** are collected (do not stop at the first one) and sorted by line.

### Task 3: Auto-layout

**Files:**
- Create: `src/persistence/dsl/layout.ts`
- Modify: `src/persistence/dsl/parse.ts` (`parseGraphDsl` returns `layoutGraph(graph, placed)` when there are no errors)
- Test: `tests/persistence/dsl-layout.test.ts`

**Interfaces:**
- Consumes: `parseDocument` (Task 2), `COL`, `ROW` (Task 1).
- Produces: `export function layoutGraph(graph: Graph, placed: ReadonlySet<NodeId>): Graph`. It returns a new graph where every node not in `placed` gets a position, and placed nodes are untouched.

**Algorithm** (spec §8):
1. **Back edges.** Run a DFS from each node in declaration order, following edges in declaration order. An edge to a node on the current stack is a back edge and is ignored from here on.
2. **Column** = the longest path from a node with no incoming (non-back) edges. Nodes with no edges at all are *isolated*.
3. **Row order per column.** Start with declaration order. Then, for columns 1..max, do one stable sort by the mean row index of predecessors in earlier columns (nodes without predecessors keep their relative order after those with them).
4. **Occupied cells.** A placed node occupies cell `(round(x / COL), round(y / ROW))`. Each unplaced, non-isolated node takes the first free row of its column, in sorted order.
5. **Isolated nodes** go in column 0, rows starting at (max occupied row across all columns) + 1.
6. **Position** = `{ x: col * COL, y: row * ROW }`.

### Task 4: Printer and round-trip

**Files:**
- Create: `src/persistence/dsl/print.ts`, `src/persistence/dsl/index.ts`
- Test: `tests/persistence/dsl-print.test.ts`

**Interfaces:**
- Consumes: `formatFieldValue`, `quoteIfNeeded` (Task 1), `parseGraphDsl`, `slugify`, `TYPE_KEYWORDS` (Task 2), `defaultRegistry`, `defaultConfig`.
- Produces:
  - `export function printGraphDsl(graph: Graph): string`
  - `index.ts` re-exports `parseGraphDsl`, `printGraphDsl`, `GraphDslError`, `GraphDslErrorCode`, `GraphDslResult`.

**Format** (spec §9):
1. `@architecture v1`, then a blank line.
2. **One declaration per node**, in graph order: `<type> <name>[ as <alias>] at <col>,<row>`.
   - `col`/`row` = `x / COL`, `y / ROW`, rounded to 2 decimals and printed without trailing zeros.
   - **Alias:** only for nodes whose name is shared. It is the node id when that matches `/^[\p{L}\p{N}_-]+$/u`, otherwise `slugify(id)`, made unique.
   - **Config lines** (2-space indent) list the registry fields in order, except `name`, whose value differs from `defaultConfig(def)` (deep equality). Fields unknown to the registry are skipped.
   - **`behavior`** prints `  behavior:` and each line of the text (without its final `\n`) prefixed by 4 spaces. Blank lines print empty.
   - A node with config lines has one blank line before and after it, never two in a row.
3. **Edges:** a blank line, then one line per source, in order of each source's first edge: `<ref> --> <target>[ [attrs]], …`.
   - `ref` is the alias when there is one, else the name.
   - Attrs use the short form, except: a path not starting with `/` → `path X`; an event starting with `/` or matching `/^x\d/` → `event X`; values with whitespace/`,`/`]` are quoted.
4. **Names** are quoted (`quoteIfNeeded`) when they contain `,` `"` `[` `]` `#` or `-->`, have leading/trailing spaces, or match `/\s(as|at)\s/` or `/\s(as|at)$/`.
5. **Unknown node types** print their raw `type` (re-import reports `unknown-type`, as the spec allows).
